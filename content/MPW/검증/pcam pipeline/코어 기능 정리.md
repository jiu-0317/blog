

**1. MIPI CSI-2 RX Subsystem (PG232)**

파이프라인의 입구입니다. MIPI CSI-2 카메라 센서에서 오는 고속 시리얼 신호(D-PHY/C-PHY)를 받아서 프로토콜을 디코딩하고, FPGA 내부에서 다루기 쉬운 **AXI4-Stream 비디오 데이터로 변환**해 출력합니다. 지난번에 설명드린 것처럼 D-PHY, CSI-2 Controller, Video Format Bridge 등이 내부에 통합된 서브시스템이고, 출력은 아직 RAW(Bayer) 데이터예요. 참고로 MIPI 프로토콜은 입력단에서 스로틀링(throttling)이 불가능하기 때문에, 이 서브시스템 뒤에 연결되는 모듈은 센서가 만들어내는 데이터를 감당할 충분한 대역폭을 확보하고 있어야 합니다.

**2. Sensor Demosaic (PG286)**

Bayer 센서의 색 복원 블록입니다. 이미지 센서는 픽셀마다 컬러 필터(CFA)가 하나씩 덮여 있어서 각 픽셀이 R, G, B 중 **한 가지 색 정보만** 측정합니다. Demosaic 코어는 5x5 보간(interpolation) 윈도우를 사용해 이웃 픽셀 정보로부터 각 픽셀의 나머지 두 색 성분을 재구성하여, RAW Bayer 입력을 완전한 RGB 영상으로 만들어 줍니다. 5x5 이웃 내 색차 분산(chrominance variance)을 최소화하는 방식으로 지퍼 아티팩트나 색 앨리어싱을 억제하도록 설계되어 있고, 센서마다 다른 4가지 Bayer phase(첫 픽셀이 R/G/B 중 무엇으로 시작하는지)를 모두 지원하며 이는 레지스터로 런타임 설정 가능합니다.

**3. Gamma LUT (UG1449, PG285)**

디스플레이 응답 특성에 맞게 영상 데이터를 변환하는 감마 보정 블록입니다. **룩업 테이블(LUT) 구조**로 구현되어 있어서, 테이블을 프로그래밍하면 감마 커브뿐 아니라 사용자가 정의한 임의의 변환 함수도 적용할 수 있습니다. R, G, B 세 채널이 각각 독립적인 LUT를 가지므로 채널별로 다른 커브를 줄 수도 있어요. (프로젝트에 PG285 원문은 없고 UG1449의 요약 내용을 참고했습니다.)

**4. VPSS — Video Processing Subsystem (PG231)**

범용 영상 처리 서브시스템으로, 여러 처리 IP 서브코어를 하나의 계층적 IP로 묶어 단일 GUI에서 설정하는 구조입니다. 지원 기능은 **스케일링(업/다운), 색공간 변환·보정(RGB↔YUV), 크로마 리샘플링(4:4:4/4:2:2/4:2:0), 디인터레이싱, 프레임 레이트 변환** 등이에요. Vivado에서 "Full Fledged"(모든 기능 포함) 또는 "Scaler Only" 같은 구성으로 필요한 기능만 골라 리소스를 절약할 수 있습니다. 카메라 파이프라인에서는 주로 색공간 변환(예: Demosaic의 RGB 출력을 디스플레이나 인코더가 원하는 YUV로 변환)이나 해상도 스케일링 용도로 씁니다. 앞서 보신 PG232 예제 디자인에서 V_Proc_SS가 CSC(색공간 변환)로 쓰인 게 바로 이거예요.

**5. Video Frame Buffer Write (PG278)**

파이프라인의 종착점으로, **AXI4-Stream 비디오를 DDR 메모리에 DMA로 써 넣는** 코어입니다. 스트림으로 흘러오는 픽셀 데이터를 RGB8, YUYV8, Y_UV8_420 같은 프로그래밍 가능한 메모리 포맷으로 패킹해서 메모리맵 AXI4 인터페이스를 통해 지정된 버퍼 주소에 저장합니다. 이렇게 메모리에 프레임이 쌓이면 PS(소프트웨어)나 다른 IP(NN 가속기 등)가 그 데이터를 읽어 처리할 수 있게 되죠. 반대 방향(메모리 → 스트림)은 짝꿍인 Video Frame Buffer Read가 담당합니다. 구형 AXI VDMA와 달리 픽셀 패킹/언패킹을 IP가 알아서 해 주는 게 장점이지만, 읽기/쓰기 채널이 분리된 단방향 IP이고 Genlock 동기화(같은 버퍼에 동시 읽기/쓰기 방지)는 소프트웨어에서 직접 구현해야 한다는 점을 문서가 명시하고 있습니다. 필요 대역폭은 `fps × height × stride`로 계산하고요.
