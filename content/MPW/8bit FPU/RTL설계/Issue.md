
# 1. IR의 Zero 처리 누락으로 인한 ACC_R에서의 NaN 전파 문제

IR.v

```verilog
assign exp_conv = {1'b0, exp_e4m3} + 5'd8;
```

부분의 E4M3 --> E5M3 bias보정 로직에서 exp가 모두 0일 때도(zero) exp에 8을 더함으로 인해 0이 아닌 극소값이 만들어진다.

ex)  
exp_conv = {1'b0, exp_e4m3} + 5'd8; // 0 + 8 = 8  
→ E5M3: {0, 01000, 000} = 1.0 × 2^(8-15) = 2^(-7) --> 0.0078

이렇게 0이 계속 들어오면 원래는 0이 출력 되어야 하지만, 극소값이 계속 더해지게 되고, 이는 ACC_R에서 연쇄적인 문제를 낳게 된다.  

```verilog
always @(*) begin
    if (exp_e4m3<=0) begin
        e4m3 = {i_data[8], 4'b1111, 3'b111}; // NaN
```

ACC_R에서는 E5M3 --> E4M3 로 변환을 위해 exp에서 8을 빼게 되는데, 이때 극소값은 exp를 빼는 과정에서 underflow가 나게 된다.  
이는 0으로 처리되어야 하지만 현재 NaN값으로 처리되어 0이 연속적으로 들어오는 경우 또는 극소값이 들어오는 경우 모두 NaN이 전파되는 문제가 있다.

해당 문제는 IR에서 0인 경우 exp에 8을 다하지 않게 하고 ACC_R에서 극소값인 경우 NaN이 아닌 0으로 saturation 하게 하는 방식으로 처리할 예정이다.

# 2. ACC 오차 누적 문제

ACC_adder에서는 매번 더할 때 마다 라운딩을 하고있다.  
라운딩을 할 때마다 truncation이 발생하며 오차가 누적된다.  
뿐만 아니라 더해지는 순서에 따라 오차가 달라지며 결과도 바뀌게 된다.

이걸 고정소수점으로 바꿨더니 면적이 너무 늘었다. 

![[Pasted image 20260601212103.png]]

이렇게 말고 그냥 mant를 충분히 늘려야겠다.

mant를 7비트로 늘리고 ACC_R에서 포맷 축소할 때 라운딩을 거치게 해놨다. 

이렇게 하니까 면적이 6만정도 늘기는 했는데 정확도가 많이 향상되어서 tb 테스트케이스 중 2개를 더 통과하게 되었다.
