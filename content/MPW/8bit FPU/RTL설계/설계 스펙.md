

# 8-bit MAC 설계 아키텍처 분석


이 사진에 대한 설명이야. 이 구조로 verilog 설계를 할 때 어떤 module과 각 모듈에 어떤 in/out port가 있어야 할지, 그리고 이 설계에서 어떤 control signal이 있으면 될지, state machine은 어떻게 구성되면 될지 알려줘. 코드를 작성하라는게 아니라 너는 설계를 도와주는거야. Decoder는 SPI로 받아온(command는 load weight 또는 input) data, command, mode(output이 E5M2인지 E4M3인지), address를 분리한다. Decoder 다음에 있는 DFF는 formatter에 들어갈 valid한 E4M3 또는 E5M2 값이 들어간다. formatter는 DFF에서 값을 가져와 E5M2또는 E4M3를 E5M3로 확장. formatter다음 Router는 address에 맞는 weight/input DFF에 확장된 값을 넣어준다. 그러면 weight 와 input DFF에 각각 값이 저장된다. weight와 input DFF에 값이 다 로드되었으면 SPI로 compute command를 보낸다. 그러면 FPU가 연산을 시작하고, output DFF에 valid한 결과값이 저장된다. 그리고 accumulate command를 보내면 이게 순차적으로 ACC에 들어가서 누적합이 된다. 그러면 ACC다음에 있는 DFF에 누적 합의 결과가 저장되고, 이게 필터 연산 1번 한 결과가 되는거야. 이걸 다시 SPI로 내보내는거야. SPI 코드는 이미 주어져있어. 이 코드를 2byte를 주고받는걸로 수정해서 사용할거야.

## SPI 프로토콜 (2 Byte = 16 bit)

| Field | Bits | Description |
|-------|------|-------------|
| CMD | [15:14] | `00`=NOP, `01`=LOAD_WEIGHT, `10`=LOAD_INPUT, `11`=COMPUTE/ACC/READ |
| SUB_CMD | [13:12] | CMD=`11`일 때: `00`=COMPUTE, `01`=ACCUMULATE, `10`=READ_RESULT |
| MODE | [11] | `0`=E4M3, `1`=E5M2 |
| ADDR | [10:8] | DFF 주소 (0~8, 9개) |
| DATA | [7:0] | 8-bit 값 (E4M3 or E5M2) |

## 모듈 목록 및 포트

### 1. `top_mac` (최상위)
SPI와 내부 데이터패스를 연결하는 최상위 모듈.

### 2. `spi_slave` (기존 코드 수정, 32bit → 16bit)
| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | 시스템 클럭, 리셋 |
| i_SCLK, i_MOSI, i_SSn | in | 1 | SPI 물리 신호 |
| o_MISO | out | 1 | SPI 출력 |
| o_rx_data | out | 16 | 수신 데이터 |
| o_rx_valid | out | 1 | 수신 완료 펄스 |
| i_tx_data | in | 16 | 송신 데이터 |

### 3. `decoder`
SPI 수신 데이터를 파싱.

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_rx_data | in | 16 | SPI 수신 데이터 |
| i_rx_valid | in | 1 | 수신 완료 |
| o_cmd | out | 2 | 명령 코드 |
| o_sub_cmd | out | 2 | 서브 명령 |
| o_mode | out | 1 | E4M3/E5M2 선택 |
| o_addr | out | 4 | 대상 DFF 주소 |
| o_data | out | 8 | 8-bit 원본 데이터 |
| o_valid | out | 1 | 디코딩 완료 |

### 4. `formatter_in` (입력측 포맷 변환)
E4M3 또는 E5M2 → E5M3 (9-bit 내부 표현) 확장.

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_mode | in | 1 | 입력 포맷 선택 |
| i_data | in | 8 | 원본 FP8 값 |
| i_valid | in | 1 | |
| o_data | out | 9 | E5M3 확장 값 |
| o_valid | out | 1 | |

### 5. `router` (데이터 라우팅)
address 기반으로 weight 또는 input DFF에 값을 분배.

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_cmd | in | 2 | LOAD_WEIGHT / LOAD_INPUT 구분 |
| i_addr | in | 4 | 대상 DFF 인덱스 (0~8) |
| i_data | in | 9 | E5M3 데이터 |
| i_valid | in | 1 | |
| o_w_data | out | 9 | weight DFF로 가는 데이터 |
| o_w_addr | out | 4 | weight DFF 주소 |
| o_w_wen | out | 1 | weight write enable |
| o_i_data | out | 9 | input DFF로 가는 데이터 |
| o_i_addr | out | 4 | input DFF 주소 |
| o_i_wen | out | 1 | input write enable |

### 6. `reg_file_weight` / `reg_file_input` (각각 9개 DFF 뱅크)
| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_data | in | 9 | 쓸 데이터 (E5M3) |
| i_addr | in | 4 | DFF 인덱스 |
| i_wen | in | 1 | write enable |
| o_data[0]~[8] | out | 9×9 | 9개 DFF 출력 (FPU로 상시 연결) |

### 7. `fpu` (×9 인스턴스, 8-bit 곱셈기)
| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_weight | in | 9 | E5M3 weight |
| i_input | in | 9 | E5M3 input |
| i_start | in | 1 | 연산 시작 신호 |
| o_result | out | 16 | 곱셈 결과 (더 넓은 비트폭) |
| o_valid | out | 1 | 연산 완료 |

### 8. `output_reg_file` (출력 DFF 뱅크, 9개)
| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_data[0]~[8] | in | 16×9 | FPU 결과 |
| i_wen[0]~[8] | in | 9 | 각 FPU valid |
| o_data[0]~[8] | out | 16×9 | ACC로 가는 출력 |

### 9. `accumulator`
9개 출력을 순차적으로 누적합.

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_clk, i_rstn | in | 1 | |
| i_data | in | 16 | 현재 입력값 (MUX에서 선택된) |
| i_start | in | 1 | 누적 시작 |
| i_clear | in | 1 | 누적값 초기화 |
| o_result | out | 20 | 누적합 (오버플로 방지 확장) |
| o_done | out | 1 | 9개 누적 완료 |

내부에 **카운터** (0→8) 와 **MUX**가 필요: output DFF 9개 중 하나를 순차 선택.

### 10. `formatter_out` (출력측 포맷 변환)
내부 결과 → E5M2 또는 E4M3로 변환 (truncation/rounding).

| Port | Dir | Width | Description |
|------|-----|-------|-------------|
| i_mode | in | 1 | 출력 포맷 선택 |
| i_data | in | 20 | 누적 결과 |
| i_valid | in | 1 | |
| o_data | out | 8 | 포맷 변환된 결과 |
| o_valid | out | 1 | |

## Control Signals (주요 제어 신호)

```
ctrl_cmd[1:0]       ← decoder 출력, 현재 명령
ctrl_sub_cmd[1:0]   ← decoder 출력, 서브 명령
ctrl_mode           ← E4M3/E5M2 모드 레지스터 (load 시 래치)

w_wen               ← weight DFF write enable
i_wen               ← input DFF write enable
fpu_start           ← 9개 FPU 동시 시작
acc_start           ← accumulator 순차 누적 시작
acc_clear           ← accumulator 초기화

fpu_done            ← 모든 FPU 연산 완료 (AND of 9 valid)
acc_done            ← 누적 완료

tx_valid            ← SPI 송신 데이터 준비 완료
tx_data[15:0]       ← SPI로 보낼 결과
```

## State Machine (`main_ctrl`)

```
        ┌──────────┐
        │   IDLE   │◄──────────────────────────┐
        └────┬─────┘                           │
             │ rx_valid                        │
             ▼                                 │
        ┌──────────┐                           │
        │  DECODE  │                           │
        └────┬─────┘                           │
             │                                 │
     ┌───────┼───────────┬──────────┐          │
     ▼       ▼           ▼          ▼          │
 ┌───────┐ ┌───────┐ ┌───────┐ ┌────────┐     │
 │LOAD_W │ │LOAD_I │ │COMPUTE│ │READ_RES│     │
 └───┬───┘ └───┬───┘ └───┬───┘ └───┬────┘     │
     │         │         │         │           │
     │         │         ▼         │           │
     │         │    ┌─────────┐    │           │
     │         │    │FPU_WAIT │    │           │
     │         │    └────┬────┘    │           │
     │         │         │fpu_done │           │
     │         │         ▼         │           │
     │         │    ┌─────────┐    │           │
     │         │    │  ACCUM  │    │           │
     │         │    └────┬────┘    │           │
     │         │         │acc_done │           │
     │         │         ▼         │           │
     │         │    ┌─────────┐    │           │
     │         │    │ FORMAT  │    ▼           │
     │         │    └────┬────┘ ┌──────┐       │
     │         │         │      │TX_OUT│       │
     │         │         ▼      └──┬───┘       │
     └─────────┴─────────┴────────┴───►────────┘
```

### 각 상태 설명

| State | 동작 | 전이 조건 |
|-------|------|-----------|
| **IDLE** | 대기. SPI 수신 대기 | `rx_valid` → DECODE |
| **DECODE** | 명령 파싱, cmd에 따라 분기 | cmd 값에 따라 분기 |
| **LOAD_W** | formatter → router → weight DFF 쓰기 | 완료 → IDLE |
| **LOAD_I** | formatter → router → input DFF 쓰기 | 완료 → IDLE |
| **COMPUTE** | `fpu_start` 어서트, 9개 FPU 동시 연산 시작 | 즉시 → FPU_WAIT |
| **FPU_WAIT** | FPU 연산 완료 대기, 결과를 output DFF에 저장 | `fpu_done` → ACCUM |
| **ACCUM** | 카운터 0→8, output DFF를 순차적으로 ACC에 입력 | `acc_done` → FORMAT |
| **FORMAT** | ACC 결과를 formatter_out으로 변환 | 완료 → TX_OUT |
| **TX_OUT** | 변환 결과를 SPI tx_data에 로드 | 완료 → IDLE |
| **READ_RES** | 현재 ACC 결과를 SPI로 전송 | 완료 → IDLE |

## 설계 시 고려사항

1. **COMPUTE와 ACCUMULATE 분리 여부**: 다이어그램상 별도 command이지만, compute 후 자동으로 accumulate하는 것이 효율적. 만약 분리하면 COMPUTE→FPU_WAIT→IDLE, 이후 별도 ACC command로 ACCUM 진입하는 구조도 가능.

2. **FPU 결과 비트폭**: E5M3(9bit) × E5M3(9bit) 곱셈 결과는 mantissa 확장이 필요. 내부적으로 16bit 정도면 충분하고, ACC 누적 시 오버플로 방지를 위해 20bit 이상으로 확장.

3. **ACC 내부 MUX**: 9개 output DFF 중 하나를 선택하는 9:1 MUX + 3~4bit 카운터로 구현. 매 클럭마다 하나씩 누적.

4. **SPI 수정**: 기존 32bit → 16bit로 변경. `RBUF`/`TBUF`를 `[15:0]`으로, 카운터 기반 16-bit 전송 완료 감지 추가 권장.
