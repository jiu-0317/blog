# 1clk pulse generator

![[Pasted image 20260524162511.png]]

```verilog
module pulse_detector (
    input  wire clk,
    input  wire rst_n,
    input  wire sig_in,
    output wire pulse_out
);

    reg sig_d;

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            sig_d <= 1'b0;
        else
            sig_d <= sig_in;
    end

    assign pulse_out = sig_in & ~sig_d;

endmodule

```


● 설계 방향 논의 좋습니다. 논문 관점에서 객관적으로 — 무엇이 기여가 되고 무엇이 안 되는지부터 솔직하게 가르고, 그 위에 쓸 수 있는 방향을
  제시하겠습니다.

  먼저: 무엇이 논문이 "안 되는가"

  - 성능/throughput은 story가 될 수 없습니다. SPI 직렬 입력 + 단일 누산기 구조라 처리량은 I/O에 묶입니다. "빠른 가속기"로 포지셔닝하면 reviewer가
  바로 깰 겁니다.
  - "FP8 MAC를 만들었다" 자체는 신규성이 아닙니다. OCP FP8, Hopper(E4M3/E5M2)로 이미 표준화된 영역입니다.
  - 지금 상태(90%)는 동작하는 RTL + 기능 검증 tb까지인데, 논문이 되려면 정량 비교(PPA·정확도)와 baseline이 빠져 있습니다. 이게 남은 핵심
  10%입니다.

  즉 이 설계는 성능이 아니라 "면적/에너지 효율 + 저정밀 산술 기법" 으로만 논문이 됩니다. 다행히 그쪽으로는 실제 차별점이 있습니다.

  쓸 수 있는 차별점 (이 설계의 진짜 자산)

  1. LUT 기반 가수 곱셈 (mant_mult_lut) — 가장 구체적이고 강한 hook. 3bit 가수 곱셈+정규화+라운딩+오버플로우를 곱셈기 대신 36-entry LUT 하나로
  접고, 교환법칙으로 엔트리를 절반으로 줄였습니다. M=3 같은 극저정밀에서 LUT가 multiplier+normalizer보다 작고 빠를 수 있다는 건 정량화할 가치가
  있는 micro-arch 기여입니다.
  2. 포맷-무관 혼합정밀 (E4M3/E5M2 입력 → 공통 E5M3 → E5M7 누산 → E4M3/E5M2 출력) — 입력 포맷을 내부에서 통일하고 하드웨어(특히 ACC_R의 라운딩
  회로)를 공유한 점.
  3. 넓은 누산 후 1회 라운딩 (E5M7) — dot-product에서 정밀도를 보존하는 "accumulate-wide, round-once" 전략.
  4. 면적·핀 제약형 edge MAC offload (SPI 부착) — 정직하게 "작은 임베디드 가속기"로 포지셔닝.

  논문 방향 3가지 (야심·신규성 순)

  방향 A — "FP8 MAC를 위한 LUT 기반 가수 곱셈기" (추천, 가장 단단함)
  - 주장: 극저정밀 FP8에서 곱셈+정규화+라운딩을 단일 LUT로 통합하면 곱셈기 기반 대비 면적/에너지가 줄어든다.
  - 필요 실험: ① conventional multiplier+normalizer MAC를 baseline으로 합성 → LUT-MAC와 area/power/freq 비교. ② mantissa 폭(M=2,3,4,5)을 스윕해서
  "LUT가 유리한 crossover point"를 보이면 일반화된 결과가 됩니다 (M이 커지면 LUT가 폭발하므로 한계도 정직하게 제시 → 오히려 설득력↑).
  - 강점: 범위가 좁고 명확, 학부/석사 수준에서 완결 가능.

  방향 B — "혼합정밀·구성가능 출력 FP8 MAC 유닛"
  - 주장: E4M3/E5M2를 하나의 datapath로 처리하고 E5M7 넓은 누산으로 정밀도를 지키며 출력 포맷을 런타임 선택.
  - 필요 실험: 정확도 평가(이미 tb에 e4m3_to_real/e5m2_to_real·오차 체크 인프라 있음 → FP32 reference 대비 오차 분포, round-once vs round-each-add
  비교), 하드웨어 공유로 줄인 면적.
  - 강점: tb 자산을 그대로 활용. 단, 신규성은 A보다 약함(혼합정밀 자체는 흔함).

  방향 C — "직렬 I/O 제약 하 MAC 가속기의 설계공간 탐색" (우리가 한 논의를 그대로 기여로)
  - 주장: I/O가 직렬(SPI) 병목인 가속기에서는 naive한 9-병렬 FPU가 면적만 쓰고 이득이 없으며, 시분할 단일 MAC이 area-efficiency Pareto-optimal이다
  — 이걸 PPA 데이터로 증명.
  - 필요 실험: 9-FPU 병렬 / 1-FPU 시분할 / (AUTO 스트리밍) 세 변형을 합성·비교, area·energy/MAC·실효 throughput 표.
  - 강점: 우리가 앞서 발견한 "병렬 곱 + 직렬 누산은 worst-of-both"라는 통찰이 분석적 결과가 됨. 교육적·실용적 가치 큼. 단독으로는 신규성이 약해
  A의 보조 섹션(설계공간 탐색)으로 넣는 게 가장 강력합니다.

  가장 추천하는 조합

  A를 본론, C를 design-space 섹션, B의 정확도 평가를 뒷받침으로 묶는 구성:

  ▎ "면적·핀 제약 edge 환경을 위한 LUT 기반 혼합정밀 FP8 MAC 가속기"
  ▎ — 핵심 기여: ① LUT 가수 곱셈(면적/에너지), ② 직렬 I/O 하 단일-MAC이 병렬 대비 우월함을 보이는 설계공간 분석, ③ E5M7 넓은 누산의 정확도.

  이러면 "성능"이 아니라 "효율·정밀도·설계 통찰"이라는, 이 설계가 실제로 강한 축으로 story가 정렬됩니다.

  논문이 되려면 채워야 할 10%

  1. 합성 PPA (가장 중요): 적어도 한 공정(예: 오픈 PDK Sky130 또는 보유 PDK)으로 area/power/max-freq. baseline(곱셈기 MAC) 대비 비교가 핵심.
  2. 정확도 정량화: FP32 reference 대비 dot-product 오차, mantissa 스윕, round-once 효과.
  3. 에너지/MAC, 면적/MAC 정규화 지표.
  4. (선택) 작은 NN 레이어 추론에 offload하는 워크로드 데모.

  솔직한 venue 보정

  - 현재 자산(단일 MAC, SPI, 소형)으로는 top-tier(ISSCC/VLSI/MICRO)는 무리입니다.
  - 현실적 타깃: ISOCC, IEEE/IEIE 국내·아시아권 학회, 학생 설계 콘테스트, 또는 tapeout 리포트/워크숍 short paper. LUT 기법 + PPA가 탄탄하면 이
  범위에서 충분히 경쟁력 있습니다.

이게 전형적인 CDC(Clock Domain Crossing) 지점입니다. 서로 비동기인 두 클락 사이에서 데이터를 넘기는 거라, 타이밍 운이 나쁘면 메타스테이블/깨진 값이 나올 수 있어요.

"SCLK를 클락으로 쓰지 말고, 시스템 클락으로 샘플링해서 써라"

제안의 핵심은 i_sclk를 클락 자리에 넣지 말고, 그냥 평범한 입력 신호로 취급하라는 거예요. 대신 빠른 시스템 클락으로 그 신호를 계속 들여다보면서(오버샘플링) 엣지를 검출합니다. 개념적으로 이런 형태:

verilog

```verilog
// SCLK를 시스템 클락으로 샘플 (동기화 + 직전 값 보관)
reg sclk_d1, sclk_d2;
always @(posedge i_clk) begin
    sclk_d1 <= i_sclk;
    sclk_d2 <= sclk_d1;
end

wire sclk_rising  = (sclk_d1 & ~sclk_d2);  // SCLK 상승엣지 "검출 펄스"
wire sclk_falling = (~sclk_d1 & sclk_d2);  // SCLK 하강엣지 "검출 펄스"

// 그러면 모든 플롭이 i_clk 하나로만 돌아감
always @(posedge i_clk) begin
    if (sclk_rising) RBUF <= {RBUF[14:0], i_mosi};  // "clock"이 아니라 "enable"로 사용
end
```

차이가 보이죠? `posedge i_sclk`로 돌던 게 → `posedge i_clk + if(sclk_rising)`로 바뀝니다. SCLK는 더 이상 클락이 아니라 "지금이 시프트할 타이밍이다"라는 인에이블 펄스가 돼요. 칩 전체가 i_clk 단일 클락 도메인이 됩니다.

---

**이게 왜 의미가 있나 (이게 진짜 질문이었죠)**

**1. 클락 도메인이 하나가 돼서 CDC 문제가 사라진다**

지금 line 62의 위험한 교차가 없어져요. RBUF도, o_dat도 전부 같은 i_clk로 도니까 비동기 교차가 아예 안 생깁니다. (SCLK 입력을 받아들이는 2단 플롭 sclk_d1/d2만 동기화해주면 됨.)

**2. ASIC에서 "클락"은 비싸다 — 클락 트리와 스큐 문제**

여기가 "스큐" 얘기의 핵심이에요. 칩 안에서 어떤 신호를 클락으로 쓰면, 그 신호는 모든 플롭에 거의 동시에 도착하도록 **클락 트리(clock tree)**를 따로 깔아서 균형을 맞춰줘야 해요.

지금 설계는 `posedge i_sclk`, `negedge i_sclk`, `posedge i_clk` 세 가지 엣지로 플롭이 돌아요. 이걸 다 클락으로 관리하려면 트리가 여러 개가 되고 타이밍 클로저(timing closure)가 까다로워집니다. 특히 외부에서 들어오는 SPI 클락은 패드/배선 지연이 제멋대로라, 데이터(MOSI)와 클락 사이의 도착 시간 차이 = 스큐를 통제하기 어려워요.

**3. "SPI 클락은 느리게, 시스템 클락은 빠르게" 인 이유 = 오버샘플링 조건**

시스템 클락으로 SCLK를 "샘플링"해서 엣지를 잡아내려면, 시스템 클락이 SPI 클락보다 충분히 빨라야 해요(보통 최소 2배, 실무적으론 4배 이상). 느린 신호를 빠른 시계로 여러 번 들여다봐야 엣지를 놓치지 않으니까요. 마치 나이퀴스트처럼요.

지금 테스트벤치가 딱 그 비율이에요 (tb_TOP.v):

verilog

```verilog
parameter CLK_PERIOD = 10;  // 시스템 클락 100MHz
parameter SCLK_HALF  = 50;  // SPI 클락 10MHz → 10배 오버샘플링
```

시스템 100MHz가 SPI 10MHz를 10번씩 들여다보니 엣지를 안정적으로 잡을 수 있어요.

**4. "SPI 클락을 빠르게 하면 스큐가 발생한다"는 말**

만약 SPI 클락을 시스템 클락에 가깝게 빠르게 올려버리면 두 가지가 깨져요:

- 오버샘플링 배수가 모자라서(예: 2배도 안 되면) 시스템 클락이 SCLK 엣지를 제대로 못 잡음.
- 외부 클락의 배선 지연/스큐가 한 주기에서 차지하는 비중이 커져서, 샘플링한 값이 엣지 근처에서 흔들림 → 셋업/홀드 위반·메타스테이블.

그래서 **"외부 SPI는 느리게 두고, 내부 시스템 클락만 빠르게 돌려서 그걸로 천천히 들어오는 SPI를 여유 있게 샘플링한다"**가 안전한 구조인 거예요.

---

**한 줄 요약**

지금은 SPI 클락을 진짜 클락으로 써서 칩이 2-클락-도메인이고 CDC/클락트리/스큐 부담이 있다. 제안은 SPI 클락을 (느린) 일반 입력 신호로 보고, (빠른) 시스템 클락으로 오버샘플링해서 엣지만 검출해 쓰자는 것 → 칩이 단일 클락 도메인이 되고, 외부 클락을 클락 트리에 안 태우니 스큐/타이밍 문제가 사라진다. 단 오버샘플링이 성립하려면 시스템 클락 ≫ SPI 클락이어야 한다.
